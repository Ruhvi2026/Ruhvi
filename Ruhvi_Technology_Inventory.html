1. Frontend Framework & Rendering

TechnologyCategoryPurpose & Workflow Role
Next.js 15FrameworkReact-based full-stack framework with App Router. Provides server-side rendering, static generation, incremental static regeneration (ISR), API routes, middleware, and streaming. The core application shell that handles routing, data fetching, and page rendering for all customer-facing and admin pages.
React 19LibraryUI component library. Powers all interactive elements — context providers (Auth, Cart, Wishlist), client components (Navbar, Footer, ProductCard, SearchBar, Chat), and hooks for state management and side effects.
TypeScriptLanguageStatically-typed superset of JavaScript. Used throughout the codebase for type safety, interface definitions (Product, Category, UserProfile, API request/response shapes), and improved developer experience with autocompletion and compile-time error detection.
Tailwind CSS 3FrameworkUtility-first CSS framework. Provides the design system with custom color tokens (gold, cream, charcoal, midnight, rasa, champagne, taupe) and responsive utilities. Used for all component styling via inline utility classes, with dark mode via class strategy.
PostCSSToolCSS transformation pipeline. Compiles Tailwind CSS directives and applies Autoprefixer during the build step. Configured via postcss.config.js.
AutoprefixerPluginPostCSS plugin that automatically adds vendor prefixes to CSS rules for cross-browser compatibility. Runs as part of the build pipeline.

3. Database & Storage

TechnologyCategoryPurpose & Workflow Role
Supabase (PostgreSQL)DatabasePrimary relational database. Stores all application data — users, products, categories, collections, orders, support tickets, wallet transactions, audit logs, AI provider credentials, model health, and settings. Accessed via the Supabase JS client on both server and client, with Row-Level Security (RLS) policies for data access control.
Supabase StorageFile StorageCloud object storage for user-uploaded files (product images, support attachments). Configured in next.config.js as a remote image pattern (igrkrkxdantrolbldapj.supabase.co).
Upstash RedisCacheServerless Redis instance for caching and rate limiting. Provides cacheGet/cacheSet/cacheWrap helpers for data caching, rateLimit/rateLimitSliding for API rate limiting via Redis scripts, and a read-only replica for scaling. Used to reduce database load and protect API endpoints from abuse.
Supabase RealtimeReal-timeWebSocket-based real-time subscriptions. Used in AuthContext to subscribe to postgres_changes on the users table, enabling live wallet balance and profile updates without polling.

4. Authentication & Authorization

TechnologyCategoryPurpose & Workflow Role
Firebase AuthenticationAuthPrimary authentication provider for customer-facing accounts. Handles email/password, phone (OTP), and Google SSO logins. The onAuthStateChanged listener in AuthContext manages the session lifecycle. Firebase ID tokens are exchanged for custom Supabase JWTs to enable database access.
Supabase Auth (Custom Token)AuthSecondary auth layer. The Supabase client uses an accessToken callback that fetches a custom JWT minted server-side from the Firebase ID token. This bridges Firebase authentication with Supabase's RLS policies, allowing the anon key to be used with user-scoped permissions.
joseLibraryJWT signing and verification library. Used for: (a) signing session cookies (__session) for portal/admin auth, (b) verifying session tokens in middleware for RBAC, (c) signing Google service account JWTs for Firebase Admin REST API calls, (d) decoding custom Supabase tokens in the client.
Supabase SSR (@supabase/ssr)LibraryServer-side rendering helpers for Supabase. Provides createServerClient used in middleware, server components, and route handlers to create authenticated Supabase clients with cookie-based session management.

5. AI & Machine Learning

TechnologyCategoryPurpose & Workflow Role
Google Generative AI (Gemini)AI ProviderAI model provider for the Ruhvi AI orchestration engine. Powers the customer support chatbot ("Gia"), product description generation, AI playground, and admin AI features. Accessed via @google/generative-ai SDK through the unified provider abstraction in src/lib/ai/providers/gemini.ts.
OpenAIAI ProviderAI model provider integrated into the multi-provider routing engine. Supports GPT models for AI generation tasks. Credentials are managed via the ai_provider_credentials database table with health tracking and failover.
Anthropic (Claude)AI ProviderAI model provider for Claude models. Integrated through the same unified provider interface, with support for credential rotation, error classification, and automatic failover across providers.
DeepSeekAI ProviderAI model provider for DeepSeek models. Part of the multi-provider routing strategy, enabling cost optimization and redundancy by distributing requests across providers based on priority and health status.
OpenRouterAI GatewayAI model aggregation gateway. Provides a unified API endpoint to access multiple models from different providers with a single integration point. Used as an alternative routing path within the AI orchestration engine.
Custom AI Provider FrameworkFrameworkExtensible provider abstraction (src/lib/ai/providers/custom.ts) that allows arbitrary API-compatible AI providers to be added via admin configuration. Supports OpenAI-compatible API schemas, enabling future provider additions without code changes.
AI Orchestration EngineSystemCentralized AI request handler (src/lib/ai/index.ts, ~1100 lines) implementing two-level routing: provider selection (priority/round-robin/best-responsiveness) and credential selection within a provider. Features include error classification, atomic health state transitions, model-level fallback, infinite-loop prevention, structured observability, and rate-limit/quota-exhaustion handling. Recent refinement: 5xx server errors are classified before rate-limit patterns, and Gemini RESOURCE_EXHAUSTED maps to QUOTA_EXHAUSTED.

6. Analytics, Monitoring & Error Tracking

TechnologyCategoryPurpose & Workflow Role
PostHogAnalyticsProduct analytics, session recording, and feature flags. Captures page views, custom events, and user sessions. The client-side SDK (posthog-js) is initialized in the root layout with session recording enabled (masking sensitive inputs). The server-side client (posthog-node) is used in API routes and for admin analytics queries. Includes a custom PII redaction layer to sanitize sensitive data before ingestion.
Google Analytics (GA4)AnalyticsWeb analytics via the gtag.js library. Tracks page views, e-commerce events (add_to_cart, remove_from_cart, view_item, view_item_list, purchase, search), and custom events. The GoogleAnalytics component fires on every route change with path-based tracking.
Meta Pixel (Facebook)AnalyticsConversion tracking and ad optimization pixel. Tracks PageView, AddToCart, Purchase, and other e-commerce events. Includes a server-side Conversions API (CAPI) via /api/capi for server-to-server event deduplication, improving ad attribution accuracy.
Microsoft ClarityAnalyticsSession recording and heatmap tool. Records user sessions (scroll, click, navigation) to identify usability issues and conversion friction. Loaded via afterInteractive script strategy in the root layout.
SentryError TrackingError tracking and performance monitoring. Configured for server (sentry.server.config.ts), client (sentry.client.config.ts), and edge (sentry.edge.config.ts) runtimes with 100% traces sampling. Integrates with the Next.js build pipeline via @sentry/nextjs to upload source maps and enable automatic instrumentation of Vercel Cron Monitors.

7. Push Notifications

TechnologyCategoryPurpose & Workflow Role

The FcmInit component requests permission and obtains FCM tokens for authenticated users, displays foreground notifications via toast, and integrates with a service worker (public/firebase-messaging-sw.js) for background notifications.

14. Forms, Validation & Security

TechnologyCategoryPurpose & Workflow Role
React Hook FormFormsPerformant form library with uncontrolled inputs and reduced re-renders. Used for checkout forms, auth forms (login/signup), contact forms, newsletter signup, and admin data-entry forms. Integrated with Zod validation via @hookform/resolvers.
ZodValidationTypeScript-first schema validation library. Defines environment variable schemas (src/lib/env.ts), API request/response shapes, form validation rules, and database entity schemas. Provides type inference for end-to-end type safety.
Cloudflare TurnstileSecurityPrivacy-preserving CAPTCHA alternative. Integrated via @marsidev/react-turnstile React component. Used on login, signup, and contact forms to prevent bot submissions without user friction. Verified server-side at /api/checkout/verify-turnstile.
SSRF ProtectionSecurityServer-Side Request Forgery protection module (src/lib/security/ssrf.ts). Validates and sanitizes outbound URLs to prevent internal network probing from server-side requests, particularly in AI tool calls and webhook handlers.
Content Security & Security HeadersSecuritySecurity headers applied via middleware: X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Strict-Transport-Security: max-age=31536000; includeSubDomains (HSTS). X-Robots-Tag: noindex, nofollow applied to portal subdomains to prevent indexing of internal admin interfaces. Middleware now fails closed — internal-route auth failures redirect to login.

Summary

The Ruhvi technology stack comprises 70+ distinct technologies organized into 18 categories. The architecture follows a Next.js 15 + Supabase core with a multi-provider AI orchestration engine, Firebase-first authentication bridged to Supabase via custom JWT, dual analytics and push notification systems (each with overlapping functionality), and self-hosted EspoCRM for agent support workflows. The stack is deployed on Vercel with a Docker-based EspoCRM instance on a separate VPS. Unit testing is provided via Jest + ts-jest, added alongside the existing linting/formatting pipeline.
