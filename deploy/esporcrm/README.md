# EspoCRM — Ruhvi Agent Console (deploy/)

Self-hosted EspoCRM deployment for **Ruhvi support agents only**, at
`crm.support.ruhvi.in`. The existing customer-facing support portal on
`support.ruhvi.in` is unchanged.

> **Deployment model:** EspoCRM is installed **natively** on the VPS
> (`nginx` + `php-fpm` + `MariaDB`), **not** via Docker. Use
> [`install-native.sh`](./install-native.sh) to install the Ruhvi extension.
> The old `docker-compose.yml` / `setup.sh` / `Caddyfile` are deprecated.

## Architecture

```
┌─────────────────────────────┐        ┌────────────────────────────────────┐
│  support.ruhvi.in (Vercel)  │        │ crm.support.ruhvi.in (VPS)         │
│  Next.js portal + Supabase  │◄──────►│ EspoCRM (nginx + php-fpm + MariaDB)│
│  SOURCE OF TRUTH            │  HTTPS │ (Let's Encrypt TLS)                │
└──────────────┬──────────────┘        └────────────────────────────────────┘
               │  REST + webhook (HMAC-signed)
```

- **Outbound (Ruhvi → EspoCRM):** when a support ticket is created/updated or a
  message is added, the Next.js app pushes a `Case` / `Note` to EspoCRM via its
  REST API. The Supabase ticket stores the returned `espo_case_id`.
- **Inbound (EspoCRM → Ruhvi):** the PHP hooks in `extension/Espo/Custom/Hooks/`
  POST Case/Note events to `support.ruhvi.in/api/integrations/espo/webhook`,
  HMAC-signed with the shared secret, so agent actions update the Supabase ticket.
- **Context (read-only):** the custom detail panel calls
  `support.ruhvi.in/api/integrations/espo/context` (via the
  `RuhviContext` controller) to show live customer/order/wallet data **inside a
  Case** without duplicating it in EspoCRM's DB.

## Extension config (single source of truth)

All extension secrets/URLs are read from **`custom/Espo/ruhvi-config.php`** in
the EspoCRM install dir (falling back to `RUHVI_BASE_URL` / `ESPO_WEBHOOK_SECRET`
/ `ESPO_API_KEY` environment variables for php-fpm). The file is generated by
`install-native.sh`. Do not commit real secrets.

## Install the extension (native install, on the VPS)

```bash
# 1. Copy deploy/esporcrm/ to the VPS (or git clone) — this folder.
# 2. Copy the extension sources into the EspoCRM install dir and write the config:
sudo ./install-native.sh /var/www/esporcrm
#    (runs `php app.php rebuild` automatically)
```

`install-native.sh` will:
- back up any existing `custom/Espo/Custom` and `client/custom` to
  `backups/ruhvi-<timestamp>/`,
- copy `extension/Espo/Custom/**` → `<install>/custom/Espo/`,
- copy `client-custom/**` → `<install>/client/custom/`,
- write `custom/Espo/ruhvi-config.php` with `RUHVI_BASE_URL`,
  `ESPO_WEBHOOK_SECRET`, `ESPO_API_KEY` (prompts or env vars),
- chown to `www-data`,
- run `php app.php rebuild`.

If the extension is updated later, rerun the script (or just recopy the files
and run `php app.php rebuild`).

## After install — required EspoCRM configuration

1. **Custom fields** on the Case entity (auto-provisioned by the extension
   metadata in `extension/Espo/Custom/Resources/metadata/entityDefs/Case.json`):
   - `ruhviTicketId_c` (varchar, linked to Supabase `support_tickets.id`)
   - `ruhviStatus_c` (read-only, canonical Ruhvi status)
   - `ruhviCustomerEmail_c`, `ruhviCustomerName_c`, `ruhviCustomerPhone_c`

2. **Status / priority option lists** — align the EspoCRM Case options with the
   Ruhvi statuses (New, Assigned, In Process, Pending, On Hold, Closed,
   Reopened) and priorities (Low, Normal, High, Urgent). See
   `src/lib/espo/mapping.ts` for the exact mapping.

3. **Roles / permissions** — restrict Case access to the support team:
   - Admin → Roles → create a `Ruhvi Support` role granting read + edit on Case,
     Note, and the `RuhviContext` custom controller to assigned users /
     support team members only.
   - Do **not** grant access to the underlying EspoCRM DB tables that would
     mirror Supabase data (customers/orders live in Supabase only).

4. **API credentials** — EspoCRM Admin → API Credentials → create an API Key for
   the Ruhvi app. It must match `ESPO_API_KEY` in `ruhvi-config.php` (and in the
   Vercel project env).

5. **Webhooks** — the PHP hooks fire automatically on Case/Note save, so no
   manual webhook config is required. (If you prefer not to use the PHP hooks,
   you can instead configure Admin → Webhooks pointing at
   `https://support.ruhvi.in/api/integrations/espo/webhook` with
   `X-Hook-Key` set to `ESPO_WEBHOOK_SECRET`.)

6. **Site URL** — Admin → Settings → set Site URL to
   `https://crm.support.ruhvi.in` (a bad value breaks URL generation).

## Environment variables

### VPS (written into `custom/Espo/ruhvi-config.php` by install-native.sh)

| Var | Purpose |
|-----|---------|
| `ESPO_API_KEY` | API key for EspoCRM REST API (from Admin → API Credentials) |
| `ESPO_WEBHOOK_SECRET` | Shared HMAC secret (must match Vercel) |
| `RUHVI_BASE_URL` | Ruhvi base URL for context/webhooks (`https://support.ruhvi.in`) |

> The `MYSQL_*` / `ESPO_DOMAIN` / `ESPO_SECRET` values in `.env.example` apply
> only to the deprecated docker-compose stack; on a native install the DB was
> configured during the EspoCRM web installer.

### Vercel (Ruhvi) env mirror

Add these to the Ruhvi Vercel project (Production + Preview):

```bash
ESPO_ENABLED=true
ESPO_BASE_URL=https://crm.support.ruhvi.in
ESPO_API_KEY=<from EspoCRM Admin>
ESPO_WEBHOOK_SECRET=<must match ruhvi-config.php>
RUHVI_BASE_URL=https://support.ruhvi.in
```

## Operations (native install)

```bash
systemctl status nginx php8.x-fpm mariadb   # services
tail -f /var/log/nginx/error.log            # web errors
sudo -u www-data php <install>/app.php rebuild   # rebuild EspoCRM metadata
```
